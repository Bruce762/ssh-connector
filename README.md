# ssh-connector

## SSH 金鑰驗證機制

### SSH 登入是「一個一個方法試」

當你 `ssh home-mac`，client 跟 Mac（伺服器）會照順序嘗試幾種認證方式，成功一個就進去：

```
1. publickey            ← 先試金鑰
2. keyboard-interactive
3. password             ← 退到這裡
```

### 公鑰驗證怎麼運作（需要「兩邊都有東西」）

金鑰驗證是這樣配合的：

- **你的筆電**：拿私鑰證明「我是這把金鑰的主人」。
- **家裡 Mac**：檢查它的 `~/.ssh/authorized_keys` 裡有沒有對應的公鑰。有 → 放行；沒有 → 這個方法失敗。

> **關鍵：金鑰驗證要成立，Mac 手上必須先有你的公鑰。**

### 所以「公鑰還沒送上去」時會發生什麼

公鑰還沒進 `authorized_keys` → Mac 的 `authorized_keys` 裡找不到你這把 → `publickey` 這個方法直接失敗（不是報錯，是「這條路走不通」）。

於是 client 往下試，最後落到 `password`：

```
publickey            → Mac：我沒有你的公鑰，不行  ❌
keyboard-interactive → （通常也退掉）
password             → Mac：那你打密碼吧           ✅ ← 你就是在這裡登入的
```

這正是 `ssh-copy-id` 在步驟 2 能成功的原因：它就是趁「還在用密碼登入」的時候，把公鑰塞進 Mac 的 `authorized_keys`。

### 整個時間線

| 階段 | Mac 有你的公鑰嗎 | 你怎麼登入 |
|---|---|---|
| 步驟 2 之前 | ❌ 沒有 | 密碼（金鑰方法自動跳過） |
| 步驟 2：`ssh-copy-id` | 用密碼登入，順手把公鑰寫上去 | 密碼 |
| 步驟 2 之後 | ✅ 有了 | 金鑰（只問你 passphrase） |
| 步驟 4：關密碼登入 | ✅ 有 | 只剩金鑰能進，密碼那條路封死 |

所以現在這個階段還不是用公鑰驗證，是用密碼——**公鑰驗證要等它送上電腦之後才會生效**。這也是為什麼步驟 4（關密碼）一定要等公鑰確定送上去、金鑰能連了才做，不然密碼關了、金鑰又還沒生效，就真的進不去了。

## 全圖（ASCII）

```
╔══════════════════════════════════════════════════════════════════════╗
║                        SSH 金鑰驗證機制                               ║
║   私鑰簽名 · 公鑰驗簽 · 秘密不出你的機器                              ║
╚══════════════════════════════════════════════════════════════════════╝

  登場 ── 兩位主角，各握一樣東西
  ┌─────────────────────────────┐   ┌─────────────────────────────┐
  │ 💻 筆電  (client)           │   │ 🖥  家裡電腦  (server)      │
  │─────────────────────────────│   │─────────────────────────────│
  │ [私鑰] home_computer_key    │   │ [名單] ~/.ssh/authorized_keys│
  │        永不離開這台         │   │        准入的公鑰清單        │
  │ [公鑰] home_computer_key.pub│   │                             │
  │        可公開，待送出       │   │  你的公鑰要先進這份名單     │
  └─────────────────────────────┘   └─────────────────────────────┘


  階段 A ── 設定  [ 只做一次 ]
  ─────────────────────────────────────────────────────────────────────
        💻 筆電                                          🖥 家裡電腦

  (1) 本機動作·不連網
      ssh-keygen 產生金鑰對
      ┌───────────────┐
      │ 私鑰 → 留筆電 │
      │ 公鑰 → 待送出 │
      └───────────────┘

  (2) 用「密碼」登入一次
      ssh-copy-id  ──── 公鑰 ────►  寫進 authorized_keys
      筆電 ============密碼登入===========================► 家裡電腦

      ✓ 完成後：家裡電腦名單裡有了你的公鑰 → 從此可走金鑰登入


  階段 B ── 每次登入  [ 每次連線都發生 · ssh home-computer ]
  ─────────────────────────────────────────────────────────────────────
        💻 筆電 (握私鑰)                              🖥 家裡電腦 (查名單)

   ①  「我想用這把公鑰登入」(先送公鑰問問看)
       筆電  ──────── 公鑰 ────────►  家裡電腦

   ②                                   〔本機〕翻 authorized_keys
                                        這把公鑰在名單裡嗎？
                                          在 → 繼續
                                          不在 → 退回密碼 ✗

   ③  「這把可以，繼續」(PK_OK)
       筆電  ◄──────── OK ──────────  家裡電腦

   ④  用私鑰對「含 session id 的資料」簽名 → 送出簽名
       筆電  ─────── 簽名 ─────────►  家裡電腦
              (session id 綁死這條連線)

   ⑤                                   〔本機〕用名單裡的公鑰驗簽
                                        簽名對 → 證明對方握有私鑰

   ⑥  簽名正確 → 放行，登入成功 ✅  (簽名錯 → 拒絕 ✗)
       筆電  ◄─────── 放行 ─────────  家裡電腦

      ✓ 簽名綁定 session id，側錄也無法騙下一條連線 → 防重放攻擊


  易混 ── config 寫「私鑰」，但送出去的是「公鑰」？
  ─────────────────────────────────────────────────────────────────────
      你 ~/.ssh/config 裡：
          IdentityFile ~/.ssh/home_computer_key   ← 指向「私鑰」

      這只是告訴 SSH「用這個身分」，不代表私鑰會被送出去。
      SSH 拿到私鑰後，內部拆成兩半、各做各的：

                    IdentityFile = 私鑰（你的完整身分）
                              │
                  SSH 從私鑰「推導出」公鑰
                              │
              ┌───────────────┴───────────────┐
              ▼                               ▼
        ① 送「公鑰」去問家裡電腦        ④ 用「私鑰」在本機簽名
          （公開，可送出）                （機密，不送！只送簽名結果）

      ● 公鑰其實藏在私鑰檔裡，隨時能算出來
        （home_computer_key.pub 只是方便複製的副本，刪了也能重生：
         ssh-keygen -y -f ~/.ssh/home_computer_key 會印出公鑰）
      ● 給 SSH 私鑰，是因為「能簽名的那半」才是私鑰；
        只給公鑰就沒法簽名了。
      ● 結論：你交出私鑰給「本機的 SSH」用，
        但真正上網的只有「公鑰 + 簽名」，私鑰全程不出門。


  補充 ── passphrase：第二道鎖
  ─────────────────────────────────────────────────────────────────────
      跟網路無關，只把「硬碟上的私鑰檔」加密。
        [你有的]  私鑰檔本身   ── 在筆電上
        [你知道的] passphrase   ── 解開私鑰用
      兩道鎖：私鑰檔被偷，沒 passphrase 也用不了。
      ssh-add：把解開後的私鑰暫存進 agent，免得每次重打。


  易混 ── 其實有「兩種」金鑰驗證，方向相反
  ─────────────────────────────────────────────────────────────────────
   ┌──────────────┬──────────────────┬────────────────────┬───────────┐
   │ 種類         │ 回答的問題       │ 靠什麼             │ 本專案    │
   ├──────────────┼──────────────────┼────────────────────┼───────────┤
   │ 主機驗證     │ 我連到的真的是   │ 電腦 host key      │ 已關閉    │
   │ (host key)   │ 我家電腦嗎？     │ + 你 known_hosts   │ (Strict…no)│
   ├──────────────┼──────────────────┼────────────────────┼───────────┤
   │ 使用者驗證   │ 連進來的真的是   │ 你的私鑰           │ 本文主題  │
   │ (user key)   │ 我本人嗎？       │ + 電腦 authorized_keys│ 你在做這個│
   └──────────────┴──────────────────┴────────────────────┴───────────┘

  ─────────────────────────────────────────────────────────────────────
  一句話：你證明身分靠「私鑰簽名、電腦公鑰驗簽」，秘密不出你的機器；
          電腦認不認你，看你的公鑰有沒有在它的 authorized_keys 名單裡。
```
